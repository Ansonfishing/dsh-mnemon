# v0.3.0：可组合记忆内核

**简体中文** | [English](../../en/releases/v0.3.0.md) | [扩展开发](../extensions.md)

v0.3.0 把原有三层系统提升为可组合记忆内核，同时保持一个安装包、默认三层行为、公开工具与现有数据格式兼容。Runtime、Documents、Memory Spaces 现在是三个可启停 Layer；现有路由由 `default-three-tier` Strategy 表达，Provider 构造通过 Registry/Factory 解耦。

## 交付内容

- 新增 wire-safe Contracts、`MemoryCatalog`、原子 `MemoryTopologyManager`、`MemoryKernel`、Guard、`MemoryPlan` 与 `MemoryReceipt`。
- Catalog、Topology 和 Guard 分别带代际边界；组件或 Guard 变化后，旧 Plan 在执行前被拒绝并要求重新规划。
- 每个 Layer 独立配置 `recall`、`write`、`projection`、`maintenance` 的 `off` / `manual` / `automatic` 参与模式。
- 模型工具和生命周期使用 `automatic` trigger；用户直接发起的 Web/RPC 数据面操作使用 `manual`，不能借工具调用绕过参与模式。
- 新增 `MemoryExtensionHost` 与 Cordis `mnemonMemory` 服务。扩展可以在 Host 挂载前或运行中贡献 Layer、Adapter、Strategy 与 Guard；热卸载推动新 generation。
- 设置页通过 `memory-system` RPC 读取实时描述符并动态渲染 Layer，不再依赖固定前端枚举。新发现 Layer 默认关闭且仅手动。
- 新增 Strategy manifest、权限边界和 deterministic replay 原语，为后续模型生成策略的 shadow/canary/回退流程建立制品接口。
- 源码拆为多个 private workspace，但 npm 仍只发布 `dsh-mnemon`，并新增 `contracts`、`kernel`、`extension-sdk`、`provider-sdk`、`strategy-sdk`、默认 Layer/Strategy 等子路径。

## DSH 0.1.1-rc.1 兼容与多模态支持

- 所有直接 `@deepseek-ai/dsh*` 开发依赖均精确固定到 0.1.1-rc.1，lockfile 只解析一套 rc.1 package family，不混入旧预发布 peer 实例。对外的 UI-primitives peer range 继续接受兼容的 0.1.0-rc.6 消费者，并显式接受 0.1.1-rc.1。
- 发布的插件仍为较旧且兼容的 DSH Host 保留 Node.js 20 engine 下限。DSH rc.1 组合则需要与上游仓库一致的 `^22.19.0 || >=24.0.0`：Node 20 Headless 实测会在 dsh-mnemon 加载前失败，因为 Host 导入 Node Zstd API 并使用 `Promise.withResolvers`。插件内部无法修复这个条件性宿主限制。
- 现有 Client 与 subagent 集成无需 API shim 即可通过 rc.1 类型检查。模型目录现在保留 DSH 可合并扩展的 `inputModalities`，设置页会为支持图片的路由标记**图片输入**。
- 本次 DSH 发布新增的第一方多模态路由是 `deepseek-official/deepseek-v4-flash-vision-exp`（`DeepSeek-V4-Flash-Vision-Exp`，文本 + 图片）。发布时请通过 `@deepseek-ai/dsh@next` 安装 DSH；npm `latest` 仍指向 0.1.0-rc.7。
- 生命周期处理接受 DSH 持久图片 attachment 引用，追加指引时保留每个原始多模态内容块，活动阈值只计算文本。原始图片字节不会写入 Mnemon 存储。
- Mnemon 的后台 AI 元信息、Agent 查询、记忆沉淀、智能选择和档案归档 Prompt 仍为纯文本。可以把视觉模型作为完整路由选中，但不会为这些任务暗中增加图片摄取。

该兼容更新不需要迁移 dsh-mnemon 数据。可选的 DSH SQLite 会话后端与本数据面独立：rc.1 使用 schema 17，仍会拒绝旧 schema 且不提供迁移；内置 profile 默认不启用。

## 升级与数据兼容

从 v0.2.13 升级不需要迁移数据。Runtime JSON/Markdown、Documents、Memory Space registry、Provider service registry、Mnemon Native Store 与远程 Provider 数据格式均未改变。

未配置 `memoryTopology` 时自动得到与旧版本等价的三层默认拓扑：三个 Layer 均启用，四个参与通道均为 `automatic`，Strategy 为 `default-three-tier`。已有 `storageScope`、`dataDir`、Provider、召回质量、生命周期、工具和界面设置继续生效。

建议升级步骤：

1. 安装 DSH 0.1.1-rc.1 前，确认 Node.js 为 `^22.19.0 || >=24.0.0`；
2. 按现有流程备份当前 Mnemon root 或导出 Mnemon Pack；
3. 更新 `dsh-mnemon` 并重启每个使用它的 DSH profile；
4. 在**设置 → 记忆系统 → Layer 拓扑**确认三个默认 Layer；
5. 在**状态**检查 Catalog/Topology generation 和 Provider；
6. 先用人工 Web/RPC 读取验证 `manual` 路径，再用对话工具验证需要的 `automatic` 路径。

`enabled=false` 只停止参与，不会删除或迁移数据。重新启用会使用原目录。降级到 v0.2.13 前建议备份，并从 YAML 移除只对 v0.3.0 有意义的扩展 Layer / Strategy 配置；本版本没有改变持久数据，因此包级回退不需要反向数据迁移。

## 扩展作者迁移

- 只从 `dsh-mnemon/*` 公共子路径导入，不依赖仓库内 `src/` 或 `packages/` 路径。
- 把组件注册交给 `mnemonMemory.register()` 返回的 disposer；不要维护进程外的第二个 Catalog。
- Strategy 只提出 JSON-safe steps，不持有数据面句柄；使用 manifest 限权，并用 replay 覆盖禁用层、自动/手动、预算与越权案例。
- executor 尊重 `AbortSignal`，让 Kernel 生成 `succeeded`、`partial`、`failed` 或 `cancelled` 回执。
- 收到 stale-plan 错误后重新规划，不要重放旧步骤。

仓库内原有 `src/memory-system/*` 只作为源码兼容 facade；第三方应使用 npm 子路径。

## 安全边界与当前限制

- Guard 只能拒绝，Strategy 无法放宽 Host 或参与模式；Guard 集合变化会使旧 Plan 失效。
- Cordis isolate 管理作用域和卸载，不隔离恶意 JavaScript。Layer executor、Provider Adapter 和 Strategy 必须来自受信任包。
- 本版本不会自动执行模型刚生成的代码；只交付 manifest、权限封装、replay 和 Kernel 权威校验。
- 任意新引擎可以先作为独立 Layer/Adapter 接入；Memory Spaces 中全新的 Provider 设置卡、动态连接 schema 与持久 registry 注册尚未泛化，九个现有 Provider 继续由内置 Catalog 管理。
- 现有 controller 数据面保持兼容，并已统一受 Layer 参与 gate 约束；把每条旧路径全部改为持久 Plan/Receipt 是后续渐进迁移，不改变本次公开行为。

- 发布包为 105 个文件，publint strict 与 attw ESM profile 均通过。DSH 0.1.1-rc.1 UI primitives 仍只产生上游缺失 source map 的开发期警告。
